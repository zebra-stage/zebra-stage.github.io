Developer Guide

HID SDK 1.0

Overview

This guide serves as a resource for integrating the HID SDK to read an HID NFC tag on Zebra devices. It provides an overview of the underlying system design, followed by a programming guide to walk developers through the entire integration lifecycle.

Architecture

This section discusses the design of the HID system, illustrating how key hardware and software components interact.

Component Matrix

Component Execution Context Primary Interface Key Responsibility
3rd-Party App App Sandbox (Client Process) Public SDK APIs Business logic, UI updates, trigger read/write
HID SDK (hidsdk.aar) App Sandbox (Client Process) AIDL Proxy / Java API Lifecycle, IPC proxying, callback management
Android Binder Kernel / Framework IPC Driver (/dev/binder) Secure inter-process communication & marshal
HID Dispatcher System / Privileged Process AIDL Stub / NCI HAL App validation, resource locking, hardware bridge
NFC Controller & SE Hardware / Firmware RF / Physical Antenna Contactless smart card interaction & cryptography

Components

3rd-Party Android Application

Role: Primary consumer of HID card services and credentials. Responsibilities:

  • Initializes the SDK client instance and initiates service connection.
  • Registers callback interfaces (“IHIDCallback” / event listeners) to receive asynchronous responses, discovery events, and card session status.
  • Issues commands for credential reading, payload extraction, and cryptographic operations.

HID SDK (hidsdk.aar)

Role: Client-side library integrated into the third-party application package. Responsibilities:

  • Abstracts low-level Android IPC and AIDL definitions into developer-friendly Java/Kotlin APIs.
  • Manages Android “ServiceConnection” lifecycle (“onServiceConnected”, “onServiceDisconnected”).
  • Handles parameter marshaling/unmarshaling, timeout detection, and exception wrapping.

Android Binder (IPC Layer)

Role: Secure, high-performance inter-process communication bridge. Responsibilities:

  • Facilitates remote procedure calls across the application sandbox boundary to the system-level HID service.
  • Enforces Android identity verification (“Binder.getCallingUid()”, “Binder.getCallingPid()”).

HID Dispatcher Service (HIDService)

Role: Dedicated system/privileged background service managing hardware access. Responsibilities:

  • Validates calling application signatures, package names, and authorization permissions.
  • Controls exclusive and shared access to the NFC interface to prevent contention.
  • Translates high-level HID operations into low-level device commands and routes execution responses back to client callbacks.

NFC Hardware & Secure Element Layer

Role: Physical NFC controller (e.g., NXP PN7160 / PN7220) and Secure Transceive subsystem. **Responsibilities:

  • Executes radio frequency (RF) polling, card activation, anti-collision, and APDU / NCI data transmission.
  • Securely processes contactless smart card interactions (PICC keys, secure credentials, Mifare/Desfire/iCLASS protocols).

Integration

Developers can integrate with the HID service (com.zebra.hidservice) using either the high-level Client SDK Wrapper or direct AIDL service binding.

Service Connection Lifecycle

  • Package Name: com.zebra.hidservice
  • Intent Action: com.zebra.hidservice.BIND
  • Threading Policy: IPC invocations that communicate with physical Secure Elements or SAM chips perform synchronous hardware I/O inside the service. When using direct AIDL, client applications must dispatch calls off the Main Android UI Thread to avoid Application Not Responding (ANR) warnings.

This guide provides a step-by-step walkthrough for integrating the HID SDK to read an HID NFC tag (iCLASS®, Seos®, and DESFire®) on enabled Zebra hardware (e.g., ET401 premium SKU).

I. Initialize the SDK

In your Activity‘s onCreate() method, create an instance of HidSdkManager. This requires an implementation of the ConnectionCallback interface to handle service connection events. The SDK will automatically attempt to bind to the HID service.

    public class MainActivity extends AppCompatActivity {
        private HidSdkManager hidSdkManager;
        private static final String TAG = "MainActivity";

        @Override
        protected void onCreate(Bundle savedInstanceState) {
            super.onCreate(savedInstanceState);
            setContentView(R.layout.activity_main);

            // Initialize the SDK Manager
            hidSdkManager = new HidSdkManager(this, new HidSdkManager.ConnectionCallback() {
                @Override
                public void onConnected() {
                    Log.d(TAG, "HID Service Connected. Ready to initialize communication.");
                    initiateSeCommunication();
                }

                @Override
                public void onDisconnected() {
                    Log.w(TAG, "HID Service Disconnected.");
                }

                @Override
                public void onError(String error) {
                    Log.e(TAG, "HID Service Connection Error: " + error);
                }
            });
        }
    }

II. Initiate Secure Element Communication

After the onConnected() callback is invoked, you must initialize communication with the secure element by calling initiateHIDCommunication(). This is an asynchronous operation that reports its result via the HidInitializationCallback.

    private void initiateSeCommunication() {
        if (hidSdkManager != null && hidSdkManager.isServiceBound()) {
            hidSdkManager.initiateHIDCommunication(new HidInitializationCallback() {
                @Override
                public void onSuccess(SEInfo seInfo) {
                    Log.d(TAG, "SE Communication Initialized Successfully.");
                }

                @Override
                public void onError(String error) {
                    Log.e(TAG, "SE Communication Initialization Failed: " + error);
                }
            });
        }
    }

III. Detect and Validate an NFC Card

Your application should use the standard Android NFC APIs to detect tags. When a tag is discovered, use the isCardHID() method to verify if it is a valid HID card. And then getCardData method to get the PACS (Physical Access Control System) data.

    @Override
    public void onTagDiscovered(Tag tag) {
        hidSdkManager.isCardHID(tag, new HidResponseCallback() {
            @Override
            public void onSuccess(SEResponse response) {
                if (response.isCardHid()) {
                    Log.d(TAG, "NFC Tag is a valid HID card.");
                    getCardData(tag);
                } else {
                    Log.w(TAG, "NFC Tag is not a valid HID card.");
                }
            }

            @Override
            public void onError(String error) {
                Log.e(TAG, "isCardHID check failed: " + error);
            }
        });
    }

IV. Read Authenticated Card Data

Once a card is confirmed to be a valid HID card, call getAuthenticatedData() to read and decrypt its contents, including the PACS (Physical Access Control System) data. The result is returned in an SEResponse object via the HidResponseCallback.

    private void getCardData(Tag tag) {
        hidSdkManager.getAuthenticatedData(tag, new HidResponseCallback() {
            @Override
            public void onSuccess(SEResponse response) {
                Log.d(TAG, "Successfully read authenticated data.");
                Log.d(TAG, "Serial Number: " + response.getSerialNumber());
            }

            @Override
            public void onError(String error) {
                Log.e(TAG, "Failed to get authenticated data: " + error);
            }
        });
    }

V. Clean Up Resources

To prevent resource leaks, call cleanup() in your Activity‘s onDestroy() method. This unbinds the SDK from the HID service and releases all allocated resources.

    @Override
    protected void onDestroy() {
        super.onDestroy();
        if (hidSdkManager != null) {
            hidSdkManager.cleanup();
        }
    }

Security

Developer implementation guidelines when integrating the HID SDK on Zebra hardware:

  • Service Validation: Ensure that your application environment checks the signature of the HID service to prevent interactions with unauthorized or malicious services.
  • Resource Cleanup: Always invoke cleanup() to unbind the service when the application context is destroyed. Unreleased resources can result in memory leaks or blocked hardware communication.
  • Error Handling: Robustly handle the onError() callbacks for all asynchronous operations, especially concerning hardware timeouts or invalid NFC tag detection.

Unlike standard Android framework services that enforce access control through declared Android Manifest permissions (e.g., <uses-permission>), the Zebra HID service (com.zebra.hidservice) implements runtime signature verification against an internal hardware-enforced allowlist.

  • Runtime Signature Verification: Every IPC transaction initiated by a calling application is authenticated at runtime by checking the caller’s public signing certificate against the provisioned AccessMgr allowlist.
  • Zero Trust Manifest Model: Declaring custom permissions in AndroidManifest.xml alone will not grant access to the HID service.
  • Certificate-Level Granularity: Access is granted to specific application signing certificates (typically release/production keystores or designated debug keys for development).

Exception Handling & Diagnostics

If an unauthorized application attempts to communicate with the service, the request is rejected immediately at runtime. This error indicates a caller authorization failure, not hardware, NFC polling, or credential-proximity issue. Do not troubleshoot antenna alignment, NFC tags, or RF parameters when this exception occurs.

Error Signature:

  • Exception: SecurityException
  • Callback Output: Surfaces via the SDK’s onError callback.
  • Error Message: "Access denied. Please verify your app is authorized to use the HID Secure Element."

Provisioning & Allowlist Registration

To grant your application package delegated access to the HID Secure Element, configure and deploy an [AccessMgr] profile to the target device:

  1. Extract Signature: Extract your application's public signing certificate using the ZebraSigTools utility.
  2. Create Profile: Build an AccessMgr authorization profile within StageNow.
  3. Generate Deployment Barcode: Generate the staging barcode containing the granted delegation rules.
  4. Stage Target Device: Scan the deployment barcode on all test devices prior to running integration tests.
