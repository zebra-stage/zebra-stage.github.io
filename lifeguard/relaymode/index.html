Using Relay Mode

LifeGuard

LAST UPDATED: Aug. 30, 2026

Overview

Relay Mode allows Zebra devices to receive LifeGuard Over-the-Air updates from a customer-hosted FTP/S or HTTP/S file server, eliminating reliance on Zebra-owned servers for pushing updates to individual devices. This provides Zebra customers with the option of maintaining localized control of their own servers for deployment of updates currently delivered through the Zebra LifeGuard service, which includes Android OS updates, security patches and firmware. Configuration of Relay Mode can be maintained by the company's existing Enterprise Mobility Management (EMM) system and Zebra OEMConfig. Once configured, the system operates autonomously, periodically polling the designated server for updates and installing them to devices according to established policies, all with on-device logging.

Requirements

  • Supported server protocols:
    • FTP or FTPS
    • HTTP or HTTPS
  • Server recommendations:
    • 500 GB available storage capacity
    • 1000 simultaneous connection capability
  • Required server components:
    • Highly scalable HTTP, HTTPS, FTP, or FTPS server software
    • Directory dedicated repository storage
    • 2 GB storage required for EACH Zebra device model to be updated (200 GB minimum)
    • An index file to catalog each stored update file and its hash and security patch level (SPL)
  • Supported device minimums:
    • Android 14 with April, 2026, update
    • Android 15 with My, 2026, update
    • FOTA 5.0.0.8 client
    • OEMConfig 15.3 client

All devices to receive updates from a company's Relay Server must be configured to do so. See Device Updates section below for details.

Relay Server Setup

Setup Synopsys

  1. Download and store "Full Update" .zip files for deployed devices from Zebra support site.
  2. Generate hash values for each of the (.zip) files.
  3. Extract service patch level (SPL, a date) for each of the (.zip) files from its release notes.
  4. Create, validate and store the filedata.xml file on the server.
  5. Configure all devices to receive updates from the Relay Server.

* Zebra.com login required for download.

Zebra recommends including only the latest update for each product in the filedata.xml file.

II. Create Hashes

c. Generating Hash Values for OS Update Files To quickly generate the required SHA-1 hash values for multiple .zip files in Windows environments, the administrator can utilize the batch script below.

Create a new text file in the same directory as the OS update .zip files.

Copy and paste the script below into the text file.

Save the file with a .bat extension (e.g., Generate_Hashes.bat).

Double-click the .bat file to execute it. A terminal window will open, and the script will compile all hash values into a newly generated file named SHA1List.txt.


@echo off
del SHA1List.txt 2>nul
echo Generating SHA1 values....
echo All values will be saved in SHA1List.txt
echo Please wait.
for %%i in (*.zip) do (
PowerShell -NoProfile -NoLogo -ExecutionPolicy unrestricted -Command "& Get-FileHash '%%i' -Algorithm SHA1" >> SHA1List.txt
)
echo Generation complete.
pause

IV. Create Filedata.xml File

Using a text editor, create a file called "Filedata.xml" and save it.

Using the information collected in Parts I–III above, assemble an XML-structured document using one of the more relevant samples below.

The Filedata.xml file catalogs the available OS updates on the Relay Server. All entries must be wrapped within a root <filedata> element.

For every OS update package, the administrator must include a child <file> element containing the following three required parameters:

XML Examples

Example A: Single OS update image


<filedata>
    <file>
        <value>NE_FULL_UPDATE_14-15-22.00-UG-U142-STD-NEM-04.zip</value>
        <hash>F832ABB95DB09D867F297B88D02138B710C2E3DF</hash>
        <spl>2026-05-01</spl>
    </file>
</filedata>

Example B: Multiple OS update images and device models


<filedata>
<!-- Device Model 1 (e.g., NEM) -->
  <file>
    <value>NE_FULL_UPDATE_14-15-22.00-UG-U142-STD-NEM-04.zip</value>
    <hash>F832ABB95DB09D867F297B88D02138B710C2E3DF</hash>
    <spl>2026-05-01</spl>
  </file>

<!-- Device Model 2 (e.g., ATH) -->
  <file>
    <value>AT_FULL_UPDATE_14-35-10.00-UG-U26-STD-ATH-04.zip</value>
    <hash>3689EA562AC62AF262E8969EFE62CF2E2F876B2D</hash>
      <spl>2025-11-05</spl>
  </file>
</filedata>

Define File Entries: Open Filedata.xml and add the root tags. For each OS update file, add a nested element containing the required metadata (filename, hash, and security patch level). (See Creating the Filedata.xml File for XML structure requirements).

Verify XML Structure: Review Filedata.xml to ensure all filenames and hash values are accurate, and the XML syntax is valid. Save the changes.

Deploy to Relay Server: Upload the finalized Filedata.xml file, along with all corresponding OS update .zip files, to the root directory (or designated target directory) on the Relay Server.

V. Configure Devices

Enabling Relay Mode on Devices Administrators can enable Relay Mode on target devices using Zebra OEMConfig through their EMM:

Push App: Deploy the Zebra OEMConfig application to target devices through your EMM console.

Configure Policy: Open the OEMConfig policy and navigate to System Configuration > Configure.

Set Lifeguard Settings: Drill down into Lifeguard Configuration > Relay Mode, enable the setting, fill in the server details, and apply the policy.

Deployment Behaviors to Expect:

FOTA UI Notification: After the configuration is successfully applied, the FOTA UI will display: "Relay mode is running." You can verify this in Settings App > System > System Updates.

Download in Progress: If the device successfully connects to the server and starts retrieving the image, a notification showing the download progress will appear.

Ready to Update: Once the download is fully complete, a notification will indicate that the device is ready for the update, showing the installation progress.

Monitoring and Troubleshooting

As a localized solution, Relay Mode does not provide centralized status reporting for update successes or failures.

Best Practices:

Validation

Administrators should utilize their existing EMM console to validate the active OS version on managed devices to confirm successful deployments.

Debugging Logs

For detailed troubleshooting, RxLogger must be used to extract local device logs. Please refer to the Zebra RxLogger Usage Guide for details.

Common Errors & Resolutions

Issue: "FTP server connection unsuccessful" notification

Resolution: Double-check your configuration settings. Ensure that the server protocol, port number, and host name are entered correctly.

Issue: "Failed to download" notification popup

Resolution:

Verify that the device has an active and stable network connection.

Check your network security settings to ensure a firewall is not blocking the download.

Ensure the device has enough free space; low memory can block downloads.

Issue: "Download file is corrupted" notification popup

Resolution:

Verify that the device has an active and stable network connection.

Check that the SHA-1 hash provided in Filedata.xml is correct.

Issue: "OS Update cannot be started due to low battery" notification popup

Resolution: Connect the device to a charger and wait until the battery level reaches at least 30%.

Issue: "Job interval is not in valid range" notification popup

Resolution: Ensure the update frequency is configured to be at least 15 minutes.

Usage Notes

Device Enrollment

Once Relay Mode is configured, the device will operate in this mode and standard cloud-based LGE updates will fail with Error Code 5151 ("Unable to perform OS update as LifeGuard OTA is configured in Relay mode").

Security

For enhanced security, it is strongly advised to use encrypted passwords for server authentication. Use the Zebra DET tool to generate encrypted passwords.

Password Encryption

Both encrypted and non-encrypted passwords are supported in the same text field. The FOTA client will automatically detect if the password is encrypted.

Full URL Support

You can provide the full URL (e.g., ftps://username:password@ipaddress:portno/) in the Server Host field. If a full URL is provided, the Username and Password fields can be left blank.

Update Package Constraints

Relay Mode does not support updates with Hotfix and Custom packages.

Baseline (U00) delta update packages are not supported.

OS downgrades are not supported.

Network Connectivity

Devices must be connected to a Wi-Fi network to access the FTP/FTPS server and download updates.
