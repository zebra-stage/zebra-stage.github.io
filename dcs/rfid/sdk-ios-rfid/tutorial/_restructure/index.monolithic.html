Getting Started

Getting Started Guide

Note: The code on this page is for tutorial purposes only. It shows how to call the SDK and is not production-ready: it leaves out error handling, threading and app lifecycle management. Review and adapt it before you use it in your app.

Overview

A step-by-step guide to building an iOS app that connects to a Zebra RFID reader and reads tags with the Zebra RFID SDK for iOS. Each step links to the tutorial page that explains it in detail.

Details

The SDK is written in Objective-C and talks to the reader over Bluetooth. All APIs are defined by the ZebraRfidSdkFramework framework. You work with one SDK object, apiInstance, which you create once and use for every call, and you receive everything the reader reports through one delegate object.

You need:

  • Xcode, and the ZebraRfidSdkFramework.xcframework from the Zebra RFID SDK for iOS package.
  • A physical iPhone or iPad. The simulator has no Bluetooth, so you can build for it but you cannot connect to a reader.
  • A supported reader (RFD40, RFD90 or RFD8500), paired with the iOS device in Settings > Bluetooth.

Step 1: Create the project

In Xcode, choose File > New > Project, select the iOS App template and choose Objective-C as the language. The samples in this tutorial are written in Objective-C.

Step 2: Add the SDK framework

  1. Drag ZebraRfidSdkFramework.xcframework into the project navigator. Select your app target when Xcode asks which targets to add it to.
  2. Select the app target, open the General tab and find Frameworks, Libraries, and Embedded Content.
  3. Set the framework to Embed & Sign. The SDK is a dynamic framework, so it has to be embedded in the app or the app fails to start.

You do not need to add CoreBluetooth or ExternalAccessory: the SDK framework already links them.

If your app also uses the barcode scanner (see Initialize Barcode SDK), add ZebraScannerFramework.xcframework in the same way.

Import <ZebraRfidSdkFramework/ZebraRfidSdkFramework.h> in the files that use the SDK, as the complete example below does.

Step 3: Configure Info.plist

Add these keys to your app's Info.plist, or enter them on the Info tab of the target:

  • UISupportedExternalAccessoryProtocols (Supported external accessory protocols): the protocols the reader and the scanner use. Add com.zebra.rfd8X00_easytext for the RFID reader, and com.zebra.scanner.SSI if you use the barcode scanner.
  • NSBluetoothAlwaysUsageDescription (Privacy - Bluetooth Always Usage Description): the text iOS shows when it asks the user for Bluetooth access. Without it iOS can close the app when it first uses Bluetooth. Add NSBluetoothPeripheralUsageDescription with the same text as well.
  • UIBackgroundModes (Required background modes): add bluetooth-central and external-accessory only if your app has to keep communicating with the reader while it is in the background.

<key>UISupportedExternalAccessoryProtocols</key>
<array>
    <string>com.zebra.rfd8X00_easytext</string>
    <string>com.zebra.scanner.SSI</string>
</array>
<key>NSBluetoothAlwaysUsageDescription</key>
<string>Uses Bluetooth to find, connect and communicate with nearby Zebra RFID readers.</string>
<key>NSBluetoothPeripheralUsageDescription</key>
<string>Uses Bluetooth to find, connect and communicate with nearby Zebra RFID readers.</string>
<key>UIBackgroundModes</key>
<array>
    <string>bluetooth-central</string>
    <string>external-accessory</string>
</array>

Build the project. If it builds, the framework is set up correctly.

Step 4: Initialize the SDK

Create the SDK object, register your delegate and subscribe for events. Then set the operation mode and enable the detection of available readers. The delegate is your view controller, which must declare <srfidISdkApiDelegate> in its @interface (see the complete example). These pages explain each part:

  1. Creating the SDK Instance
  2. Implement srfidISdkApiDelegate
  3. Set Operation Mode
  4. Enable Available Readers Detection

Step 5: Connect to a reader

Get the list of readers with Get Available Readers, then open a session with Connect. Commands work only after the session is established and the ASCII connection is open; the Connect page explains the order. To keep the connection alive when it drops, see Enable Automatic Communication Session Reestablishment.

Step 6: Check the reader

Before you read tags, you can check which reader you are connected to and which region it is set to:

  • Knowing the Software Version
  • Knowing the Reader Capabilities
  • Regulatory Configuration

Step 7: Read tags

Reading tags is an inventory. You set when it starts and stops with the trigger settings (see Trigger Configuration), subscribe for tag events, and start it with srfidStartInventory (see Inventory). The tags arrive one by one in srfidEventReadNotify:aTagData:. To see tags you need a connected reader and tags within its range, so this step works only on a physical device with a reader.

Step 8: Disconnect

When you are done, close the session with Disconnect.

Complete example

This example puts steps 4 to 8 together on one screen: a Connect, a Disconnect and a Start/Stop button, and a text view that shows a log. It needs nothing else, so you can use it as is. Replace the contents of the ViewController.h and ViewController.m files that the Xcode template created with the code below.

In ViewController.h, the view controller declares that it implements srfidISdkApiDelegate. Without this the SDK does not accept it as the delegate and the build shows a warning.


#import <UIKit/UIKit.h>
#import <ZebraRfidSdkFramework/ZebraRfidSdkFramework.h>

@interface ViewController : UIViewController <srfidISdkApiDelegate>
@end

In ViewController.m, the view controller builds its screen, creates the SDK object (Step 4), connects when you tap Connect (Step 5), starts and stops an inventory when you tap Start/Stop (Step 7) and disconnects when you tap Disconnect (Step 8). The delegate methods at the end are the ones the SDK can call. The first four are used here; the others are empty, because srfidISdkApiDelegate needs every method to be present.


#import "ViewController.h"

@implementation ViewController {
    id<srfidISdkApi> apiInstance;
    int readerID;
    BOOL isReading;
    UITextView *logView;
    UIButton *readButton;
}

#pragma mark - Screen: three buttons and a log

- (void)viewDidLoad {
    [super viewDidLoad];
    self.view.backgroundColor = UIColor.systemBackgroundColor;

    UIButton *connectButton = [self buttonWithTitle:@"Connect" action:@selector(connectTapped)];
    UIButton *disconnectButton = [self buttonWithTitle:@"Disconnect" action:@selector(disconnectTapped)];
    readButton = [self buttonWithTitle:@"Start" action:@selector(readTapped)];

    UIStackView *buttons = [[UIStackView alloc] initWithArrangedSubviews:@[connectButton, disconnectButton, readButton]];
    buttons.distribution = UIStackViewDistributionFillEqually;
    buttons.translatesAutoresizingMaskIntoConstraints = NO;

    logView = [[UITextView alloc] init];
    logView.editable = NO;
    logView.font = [UIFont monospacedSystemFontOfSize:12 weight:UIFontWeightRegular];
    logView.translatesAutoresizingMaskIntoConstraints = NO;

    [self.view addSubview:buttons];
    [self.view addSubview:logView];
    UILayoutGuide *safe = self.view.safeAreaLayoutGuide;
    [NSLayoutConstraint activateConstraints:@[
        [buttons.topAnchor constraintEqualToAnchor:safe.topAnchor constant:12],
        [buttons.leadingAnchor constraintEqualToAnchor:safe.leadingAnchor constant:12],
        [buttons.trailingAnchor constraintEqualToAnchor:safe.trailingAnchor constant:-12],
        [logView.topAnchor constraintEqualToAnchor:buttons.bottomAnchor constant:12],
        [logView.leadingAnchor constraintEqualToAnchor:safe.leadingAnchor constant:12],
        [logView.trailingAnchor constraintEqualToAnchor:safe.trailingAnchor constant:-12],
        [logView.bottomAnchor constraintEqualToAnchor:safe.bottomAnchor constant:-12],
    ]];

    [self setUpSdk];
}

- (UIButton *)buttonWithTitle:(NSString *)title action:(SEL)action {
    UIButton *button = [UIButton buttonWithType:UIButtonTypeSystem];
    [button setTitle:title forState:UIControlStateNormal];
    [button addTarget:self action:action forControlEvents:UIControlEventTouchUpInside];
    return button;
}

/* shows a line in the text view and in the Xcode console */
- (void)log:(NSString *)line {
    NSLog(@"%@", line);
    dispatch_async(dispatch_get_main_queue(), ^{
        self->logView.text = [self->logView.text stringByAppendingFormat:@"%@\n", line];
        [self->logView scrollRangeToVisible:NSMakeRange(self->logView.text.length, 0)];
    });
}

#pragma mark - Step 4: initialize the SDK

- (void)setUpSdk {
    apiInstance = [srfidSdkFactory createRfidSdkApiInstance];
    [apiInstance srfidSetDelegate:self];
    [apiInstance srfidSubsribeForEvents:SRFID_EVENT_READER_APPEARANCE | SRFID_EVENT_READER_DISAPPEARANCE |
     SRFID_EVENT_SESSION_ESTABLISHMENT | SRFID_EVENT_SESSION_TERMINATION];
    [apiInstance srfidSubsribeForEvents:SRFID_EVENT_MASK_READ | SRFID_EVENT_MASK_STATUS];
    [apiInstance srfidSetOperationalMode:SRFID_OPMODE_MFI];
    [apiInstance srfidEnableAvailableReadersDetection:YES];
    [self log:[NSString stringWithFormat:@"SDK version: %@", [apiInstance srfidGetSdkVersion]]];
}

#pragma mark - Step 5: connect (Connect button)

- (void)connectTapped {
    NSMutableArray *availableReaders = [[NSMutableArray alloc] init];
    [apiInstance srfidGetAvailableReadersList:&availableReaders];
    if (availableReaders.count == 0) {
        [self log:@"No reader available. Pair the reader in Settings > Bluetooth first."];
        return;
    }
    readerID = [(srfidReaderInfo *)availableReaders[0] getReaderID];
    SRFID_RESULT result = [apiInstance srfidEstablishCommunicationSession:readerID];
    [self log:[NSString stringWithFormat:@"Connecting to reader %d (result %d)", readerID, result]];
}

#pragma mark - Step 7: read tags (Start/Stop button)

- (void)readTapped {
    if (isReading) {
        [apiInstance srfidStopInventory:readerID aStatusMessage:nil];
        return;
    }

    /* start and stop immediately, without the handheld trigger */
    srfidStartTriggerConfig *startTrigger = [[srfidStartTriggerConfig alloc] init];
    [startTrigger setStartOnHandheldTrigger:NO];
    [startTrigger setStartDelay:0];
    [startTrigger setRepeatMonitoring:NO];
    srfidStopTriggerConfig *stopTrigger = [[srfidStopTriggerConfig alloc] init];
    [stopTrigger setStopOnHandheldTrigger:NO];
    [stopTrigger setStopOnTimeout:NO];
    [stopTrigger setStopOnTagCount:NO];
    [stopTrigger setStopOnInventoryCount:NO];
    [stopTrigger setStopOnAccessCount:NO];

    NSString *errorResponse = nil;
    SRFID_RESULT result = [apiInstance srfidSetStartTriggerConfiguration:readerID aStartTriggeConfig:startTrigger aStatusMessage:&errorResponse];
    if (result == SRFID_RESULT_SUCCESS) {
        result = [apiInstance srfidSetStopTriggerConfiguration:readerID aStopTriggeConfig:stopTrigger aStatusMessage:&errorResponse];
    }
    if (result != SRFID_RESULT_SUCCESS) {
        [self log:@"Could not set the triggers. Is a reader connected?"];
        return;
    }

    srfidReportConfig *report = [[srfidReportConfig alloc] init];
    [report setIncRSSI:YES];
    srfidAccessConfig *access = [[srfidAccessConfig alloc] init];
    [access setPower:270];
    [access setDoSelect:NO];
    result = [apiInstance srfidStartInventory:readerID aMemoryBank:SRFID_MEMORYBANK_EPC aReportConfig:report aAccessConfig:access aStatusMessage:&errorResponse];
    if (result != SRFID_RESULT_SUCCESS) {
        [self log:[NSString stringWithFormat:@"Could not start reading: %@", errorResponse ?: @"request failed"]];
    }
}

#pragma mark - Step 8: disconnect (Disconnect button)

- (void)disconnectTapped {
    [apiInstance srfidTerminateCommunicationSession:readerID];
}

#pragma mark - srfidISdkApiDelegate: the methods this example uses

- (void)srfidEventCommunicationSessionEstablished:(srfidReaderInfo *)activeReader {
    readerID = [activeReader getReaderID];
    [self log:@"Reader connected"];
    /* commands to the reader work only after the ASCII connection is established */
    [apiInstance srfidEstablishAsciiConnection:readerID];
}

- (void)srfidEventCommunicationSessionTerminated:(int)terminatedReaderID {
    [self log:@"Reader disconnected"];
}

- (void)srfidEventStatusNotify:(int)notifiedReaderID aEvent:(SRFID_EVENT_STATUS)event aNotification:(id)notificationData {
    if (event == SRFID_EVENT_STATUS_OPERATION_START || event == SRFID_EVENT_STATUS_OPERATION_STOP) {
        isReading = (event == SRFID_EVENT_STATUS_OPERATION_START);
        dispatch_async(dispatch_get_main_queue(), ^{
            [self->readButton setTitle:(self->isReading ? @"Stop" : @"Start") forState:UIControlStateNormal];
        });
        [self log:(isReading ? @"Reading started" : @"Reading stopped")];
    }
}

/* every tag the reader reports arrives here */
- (void)srfidEventReadNotify:(int)notifiedReaderID aTagData:(srfidTagData *)tagData {
    [self log:[NSString stringWithFormat:@"Tag: %@  RSSI: %d", [tagData getTagId], [tagData getPeakRSSI]]];
}

Build and run on a physical iPhone or iPad. To see tag reads you also need a paired reader and some RFID tags within its range. On the simulator the app starts and shows the SDK version, but it cannot connect to a reader. Tap Connect, wait for "Reader connected" in the log, and tap Start. Every tag the reader reports is logged with its tag ID and RSSI. Tap Stop to end the inventory.

If something does not work

  • Build error: ZebraRfidSdkFramework/ZebraRfidSdkFramework.h not found. The framework is not added to your app target (Step 2).
  • The app closes right after it starts. The framework is not set to Embed & Sign (Step 2), or Info.plist has no Bluetooth usage description (Step 3).
  • The reader is not in the list of available readers. Check that it is paired in Settings > Bluetooth, and that you set the operation mode and enabled available readers detection (Step 4).
  • Build warning: sending 'ViewController' to parameter of incompatible type id<srfidISdkApiDelegate>. ViewController.h does not declare <srfidISdkApiDelegate> (Step 4).
  • Start shows no tags. Check that "Reader connected" is in the log, that you waited for it before tapping Start, and that tags are within the range of the reader.
  • Commands fail right after connecting. Wait for srfidEventCommunicationSessionEstablished: and open the ASCII connection first (Step 5).

Creating the SDK Instance

Note: The code on this page is for tutorial purposes only. It shows how to call the SDK and is not production-ready: it leaves out error handling, threading and app lifecycle management. Review and adapt it before you use it in your app.

Overview

Creates the SDK object that every other API call goes through, using createRfidSdkApiInstance of srfidSdkFactory.

Details

Every RFID call in this tutorial is sent to one SDK object, called apiInstance in the samples. Create it with the createRfidSdkApiInstance method of srfidSdkFactory and keep a reference to it, for example as a property of your view controller or of a class that lives as long as the app. The object conforms to the srfidISdkApi protocol.

The factory and the protocol come from ZebraRfidSdkFramework, so import it where you use them:


#import <ZebraRfidSdkFramework/ZebraRfidSdkFramework.h>

Declare the reference and create the instance. The samples also use readerID, the ID of the reader you are working with. You set it when you connect (see Connect), and every later call passes it to the SDK.


id<srfidISdkApi> apiInstance;
int readerID;

- (void)createSdkInstance {
    apiInstance = [srfidSdkFactory createRfidSdkApiInstance];
}

You can read the version of the SDK from the instance with srfidGetSdkVersion:


- (void)getSdkVersion {
    NSLog(@"SDK version: %@", [apiInstance srfidGetSdkVersion]);
}

Right after creating the instance, set it up in this order. Each step has its own page:

  1. Register your delegate and subscribe for events (see Implement srfidISdkApiDelegate).
  2. Set the operation mode (see Set Operation Mode).
  3. Enable available readers detection (see Enable Available Readers Detection).

After this, the SDK reports readers through the delegate. To open a session with one of them, see Connect.

Overview

Sets up the object that receives the SDK's asynchronous notifications, using srfidSetDelegate and srfidSubsribeForEvents.

Details

The SDK supports a set of asynchronous notifications to inform the application about RFID reader related events (e.g. reception of tag data, starting of radio operation etc.) and connectivity related events (e.g. appearance of RFID reader). All supported callbacks are defined by srfidISdkApiDelegate Objective C protocol. In order to receive asynchronous notifications from the SDK the application shall perform the following steps.

Step 2: register the created object as a notification receiver via srfidSetDelegate API function.


-(void)registerOfcallbackInterfaceWithSDK {
    /* registration of callback interface with SDK */
    [apiInstance srfidSetDelegate:self];
}

Step 3: subscribe for asynchronous event of particular types via srfidSubsribeForEvents API function.

If a particular object is registered as a notification receiver the SDK will call the corresponding method of the registered object when a particular event occurs if the application is subscribed for events of this type. The SDK may deliver asynchronous events on a main thread or on one of SDK helper threads so the object that implements srfidISdkApiDelegate protocol shall be thread-safe.


-(void)subcribeForEvent {
    int notifications_mask_reader_connection = SRFID_EVENT_READER_APPEARANCE | SRFID_EVENT_READER_DISAPPEARANCE | SRFID_EVENT_SESSION_ESTABLISHMENT |
    SRFID_EVENT_SESSION_TERMINATION;
    [apiInstance srfidSubsribeForEvents:notifications_mask_reader_connection];

    /* subscribe for battery and handheld trigger related events */
    [apiInstance srfidSubsribeForEvents:(SRFID_EVENT_MASK_BATTERY | SRFID_EVENT_MASK_TRIGGER)];
    [apiInstance srfidSubsribeForEvents:(SRFID_EVENT_MASK_READ | SRFID_EVENT_MASK_STATUS | SRFID_EVENT_MASK_STATUS_OPERENDSUMMARY)];
    [apiInstance srfidSubsribeForEvents:(SRFID_EVENT_MASK_TEMPERATURE | SRFID_EVENT_MASK_POWER | SRFID_EVENT_MASK_DATABASE)];
    [apiInstance srfidSubsribeForEvents:(SRFID_EVENT_MASK_PROXIMITY)];
    [apiInstance srfidSubsribeForEvents:(SRFID_EVENT_MASK_MULTI_PROXIMITY)];
}

Connect

Note: The code on this page is for tutorial purposes only. It shows how to call the SDK and is not production-ready: it leaves out error handling, threading and app lifecycle management. Review and adapt it before you use it in your app.

Overview

Opens a communication session between the SDK and an available RFID reader, using srfidEstablishCommunicationSession.

Details

Before you connect, the reader must be paired with the iOS device and visible to the SDK as an available reader. Get the list of readers, and the reader ID of the one you want, as shown in Get Available Readers. Then pass that reader ID to srfidEstablishCommunicationSession.


- (void)connectRfidReader:(int)selectedReaderID {
    readerID = selectedReaderID;
    SRFID_RESULT result = [apiInstance srfidEstablishCommunicationSession:readerID];
    if (SRFID_RESULT_SUCCESS != result) {
        NSLog(@"Could not connect to reader %d", readerID);
    }
}

The call only starts the connection. The SDK reports that the session is open through srfidEventCommunicationSessionEstablished: of your delegate, so subscribe to SRFID_EVENT_SESSION_ESTABLISHMENT and wait for that callback before you send commands to the reader. Commands that read or change the reader (software version, capabilities, configuration and so on) also need the ASCII connection that the delegate page opens in that callback with srfidEstablishAsciiConnection.

Keep the reader ID: the other tutorials pass it as readerID to every call. To close the session, see Disconnect.

Overview

Closes the communication session with an RFID reader, using srfidTerminateCommunicationSession.

Details

Pass the reader ID of the connected reader to srfidTerminateCommunicationSession.


- (void)disconnectRfidReader:(int)selectedReaderID {
    SRFID_RESULT result = [apiInstance srfidTerminateCommunicationSession:selectedReaderID];
    if (SRFID_RESULT_SUCCESS != result) {
        NSLog(@"Could not disconnect from reader %d", selectedReaderID);
    }
}

The SDK reports that the session is closed through srfidEventCommunicationSessionTerminated: of your delegate, so subscribe to SRFID_EVENT_SESSION_TERMINATION. Do not send further commands to that reader after this callback.

Connectivity Management

Set Operation Mode

Overview

Sets the operating mode in which the SDK communicates with RFID readers, BT MFi or BT LE, using srfidSetOperationalMode.

Details

Zebra Bluetooth RFID iOS SDK is designed to support interaction with RFID readers operating in either BT MFi or BT LE mode. The SDK shall be intentionally configured to enable communication with a particular type of RFID readers via srfidSetOperationalMode API function. If operating mode of the SDK is not configured the SDK will remain disabled and will not be able to communicate with RFID readers in neither BT MFi nor BT LE modes. Following example demonstrates enabling interaction with RFID readers in BT MFi mode.

The operating mode is passed as one of the following constants:

  • SRFID_OPMODE_MFI (0x01): BT MFi readers
  • SRFID_OPMODE_BTLE (0x02): BT LE readers
  • SRFID_OPMODE_ALL (0x03): both BT MFi and BT LE readers

[apiInstance srfidSetOperationalMode:SRFID_OPMODE_MFI];

Get Available Readers

Overview

Retrieves the lists of available and active RFID readers known to the SDK, using srfidGetAvailableReadersList and srfidGetActiveReadersList.

Details

Following terms are introduced to distinguish RFID readers that are seen by the SDK via OS API and RFID readers with which the SDK has established a logical communication session and thus is able to interact. A RFID reader is called available if it is already connected to the iOS device via Bluetooth. Such RFID reader is seen by the SDK and the SDK can establish a logical communication session to interact with the RFID reader. If a logical communication session is established with already connected via Bluetooth RFID reader the RFID reader is called active.

The SDK supports simultaneous interaction with multiple active RFID readers. To distinguish various RFID readers the SDK assigns the unique integer identifier for each RFID reader when it becomes available first time.

The SDK maintains internal lists of active and available RFID readers. Following example demonstrates reception of lists of active and available RFID readers from the SDK.


-(void)getAvailableReaderList {
    /* allocate an array for storage of list of available RFID readers */
    NSMutableArray *available_readers = [[NSMutableArray alloc] init];

    /* allocate an array for storage of list of active RFID readers */
    NSMutableArray *active_readers = [[NSMutableArray alloc] init];

    /* retrieve a list of available readers */
    [apiInstance srfidGetAvailableReadersList:&available_readers];

    /* retrieve a list of active readers */
    [apiInstance srfidGetActiveReadersList:&active_readers];

    /* merge active and available readers to a single list */
    NSMutableArray *readers = [[NSMutableArray alloc] init];

    [readers addObjectsFromArray:active_readers];
    [readers addObjectsFromArray:available_readers];
    for (srfidReaderInfo *info in readers) {
        /* print the information about RFID reader represented by srfidReaderInfo object */
        NSLog(@"RFID reader is %@: ID = %d name = %@\n", (([info isActive] == YES) ? @"active" : @"available"), [info getReaderID], [info getReaderName]);
        readerID = [info getReaderID];
    }
}

Enable Available Readers Detection

Overview

Enables the SDK to automatically detect when available RFID readers appear and disappear, using srfidEnableAvailableReadersDetection.

Details

The SDK supports automatic detection of appearance and disappearance of available RFID readers. When “Available readers detection” option is enabled the SDK will update its internal list of available RFID readers and deliver a corresponding asynchronous notification once it detects connection or disconnection of a particular RFID reader to the iOS device via Bluetooth. If the option is disabled the SDK updates its internal list of available RFID readers only when it is requested by an application via srfidGetAvailableReadersList API function. Following example demonstrates enabling of automatic detection and processing of corresponding asynchronous notifications


[apiInstance srfidEnableAvailableReadersDetection:YES];

Enable Automatic Communication Session Reestablishment

Overview

Enables the SDK to automatically re-establish the communication session with the last active RFID reader that disappeared unexpectedly, using srfidEnableAutomaticSessionReestablishment.

Details

The SDK supports “Automatic communication session reestablishment” option. When the option is enabled the SDK will automatically establish a logical communication session with the last active RFID reader that had unexpectedly disappeared once the RFID reader will be recognized as available. If “Available readers detection” option is enabled the RFID reader will be recognized as available automatically when it becomes connected via Bluetooth. Otherwise the SDK will add the RFID reader to the list of available RFID readers only during discovery procedure requested by the application via srfidGetAvailableReadersList API. The option has no effect if the application has intentionally terminate a communication session with the active RFID reader via srfidTerminateCommunicationSession API function. The “Automatic communication session reestablishment” option is configured via srfidEnableAutomaticSessionReestablishment API function


-(void)enableAutomaticSessionReestablishment {
    SRFID_RESULT result = [apiInstance srfidEnableAutomaticSessionReestablishment:YES];

    if (SRFID_RESULT_SUCCESS == result) {
        NSLog(@"Automatic session reestablishment enabled");
    } else {
        NSLog(@"Failed to enable automatic session reestablishment: %d", result);
    }
}

Knowing the Software Version

Overview

Retrieves the software versions of the components of an active RFID reader, using srfidGetReaderVersionInfo.

Details

The SDK provides an ability to retrieve information about software versions of various components of a particular active RFID reader. Software version related information could be retrieved via srfidGetReaderVersionInfo API function as demonstrated in the following example.


-(void)getReaderInformation {

    /* identifier of one of active RFID readers is supposed to be stored in readerID variable */
    /* allocate object for storage of version related information */
    srfidReaderVersionInfo *version_info = [[srfidReaderVersionInfo alloc] init];
    /* an object for storage of error response received from RFID reader */
    NSString *error_response = nil;
    /* retrieve version related information */
    SRFID_RESULT result = [apiInstance srfidGetReaderVersionInfo:readerID aReaderVersionInfo:&version_info aStatusMessage:&error_response];

    if ((result == SRFID_RESULT_RESPONSE_TIMEOUT) || (result == SRFID_RESULT_FAILURE)) {
        NSLog(@"Time out or Failure");
    }
    if (SRFID_RESULT_SUCCESS == result) {
        /* print the received version related information */
        NSLog(@"Device version: %@\n", [version_info getDeviceVersion]);
        NSLog(@"NGE version: %@\n", [version_info getNGEVersion]);
        NSLog(@"Bluetooth version: %@\n", [version_info getBluetoothVersion]);
        textView_reader_information.text = [NSString stringWithFormat:@"Firmware version: %@\n NGE version: %@\n Bluetooth version: %@\n", [version_info getDeviceVersion], [version_info getNGEVersion], [version_info getBluetoothVersion]];
    }
    if (SRFID_RESULT_READER_NOT_AVAILABLE == result) {
        NSLog(@"RFID reader is not available\n");
        textView_reader_information.text = @"RFID reader not available";
    }
}

Overview

Retrieves the capabilities (read-only properties) of an active RFID reader, using srfidGetReaderCapabilitiesInfo.

Details

The SDK provides an ability to retrieve the capabilities (or read-only properties) of a particular active RFID reader. The reader capabilities include the following:

  • Serial number
  • Model name
  • Manufacturer
  • Manufacturing date
  • Device name
  • ASCII protocol version
  • Number of select records (pre-filters)
  • Minimal and maximal antenna power levels (in 0.1 dBm units)
  • Step for configuration of antenna power level (in 0.1 dBm units)
  • Version of air protocol
  • Bluetooth address
  • Maximal number of operations to be combined in a sequence

The reader capabilities could be retrieved via srfidGetReaderCapabilitiesInfo API function as demonstrated in the following example.


-(void)getReaderCapabilities {

        NSLog(@"Time out or Failure");
    }

    if (srfid_result == SRFID_RESULT_SUCCESS)
    {
        NSLog(@"Serial number: %@\n", [capabilities getSerialNumber]);
        NSLog(@"Model: %@\n", [capabilities getModel]);
        NSLog(@"Manufacturer: %@\n", [capabilities getManufacturer]);
        NSLog(@"Manufacturing date: %@\n", [capabilities getManufacturingDate]);
        NSLog(@"Device name: %@\n", [capabilities getScannerName]);
        NSLog(@"Ascii version: %@\n", [capabilities getAsciiVersion]);

Knowing Battery Status

Overview

Receives battery status from an active RFID reader, either as an asynchronous event after subscribing to events or on request, using srfidRequestBatteryStatus.

Details

A particular active RFID reader could send an asynchronous notification regarding battery status. The SDK will inform the application about received asynchronous battery status event if the application has subscribed for events of this type. The SDK also provides an ability to cause a particular active RFID reader to immediately send information about current battery status. The following examples demonstrate both requesting and processing of asynchronous battery status related notifications.

For detailed battery information from a reader that uses a PowerPrecision+ (PP+) battery, see PP + Battery Support.

Request Battery Status

The requestBatteryStatus method subscribes to battery events and asks the reader to send its battery status.


-(void)requestBatteryStatus {

    /* subscribe for battery related events */
    [apiInstance srfidSubsribeForEvents:SRFID_EVENT_MASK_BATTERY];
    /* cause RFID reader to generate asynchronous battery status notification */
    SRFID_RESULT result = [apiInstance srfidRequestBatteryStatus:readerID];

    if (SRFID_RESULT_SUCCESS == result) {
        NSLog(@"Request succeed\n");
    }
    else {
       NSLog(@"Request failed\n");
    }

}

Battery Status Event

The SDK calls srfidEventBatteryNotity: when the reader sends a battery status event. The method prints the battery level, the charging state and the event cause.


- (void)srfidEventBatteryNotity:(int)readerID aBatteryEvent:(srfidBatteryEvent *)batteryEvent {

    /* print the received information regarding battery status */

Configuring the Reader

Antenna Configuration

Overview

Gets and sets the antenna settings of an active RFID reader, using srfidGetAntennaConfiguration and srfidSetAntennaConfiguration.

Details

Following antenna related settings could be configured via the SDK:

  • Output power level (in 0.1 dBm units)
  • Index of selected link profile (RF mode)
  • Application of pre-filters (select records)
  • Tari (Type-A reference interval)

Tari value shall be set in accordance with the selected link profile, i.e. tari value shall be in the interval between minimal and maximal tari values specified by the selected link profile. If step size is supported by the selected link profile, the tari value must be a multiple of step size. Antenna settings could be retrieved and set via srfidGetAntennaConfiguration and srfidSetAntennaConfiguration API function accordingly. Following examples demonstrate retrieving current antenna settings and setting of antenna configuration with minimal output power and one of supported link profiles.

Get Antenna Configuration

The getAntennaConfig method retrieves the current antenna settings and prints them.


-(void)getAntennaConfig
{
    /* allocate object for storage of antenna settings */

        NSLog(@"Antenna tari: %d\n", [antenna_cfg getTari]);
        NSLog(@"Antenna pre-filters application: %@", ((NO == [antenna_cfg getDoSelect]) ? @"NO" : @"YES"));
    }
    else if (SRFID_RESULT_RESPONSE_ERROR == result)

        NSLog(@"Error response from RFID reader: %@\n", error_response);

Set Antenna Configuration

The setAntennaConfig method sets the output power to the reader's minimum and selects one of the supported link profiles.


-(void)setAntennaConfig {

    /* allocate object for storage of antenna settings */
    srfidAntennaConfiguration *antenna_cfg = [[srfidAntennaConfiguration alloc] init];
    /* an object for storage of error response received from RFID reader */
    NSString *error_response = nil;
    /* RF mode index to be set */
    int link_profile_idx = 0;
    /* tari to be set */
    int tari = 0;
    /* 20.0 dBm power level to be set */
    int power = 200;

    /* allocate object for storage of link profiles information */
    NSMutableArray *profiles = [[NSMutableArray alloc] init];
    /* retrieve supported link profiles */
    SRFID_RESULT result  = [apiInstance srfidGetSupportedLinkProfiles:readerID aLinkProfilesList:&profiles aStatusMessage:&error_response];

    if (SRFID_RESULT_SUCCESS == result)
    {

        if (0 < [profiles count])
        {
            srfidLinkProfile *profile = (srfidLinkProfile*)[profiles lastObject];
            link_profile_idx = [profile getRFModeIndex];
            tari = [profile getMaxTari];
        }

    }

    /* allocate object for storage of capabilities information */
    srfidReaderCapabilitiesInfo *capabilities = [[srfidReaderCapabilitiesInfo alloc] init];

    /* retrieve capabilities information */
    result = [apiInstance srfidGetReaderCapabilitiesInfo:readerID aReaderCapabilitiesInfo:&capabilities aStatusMessage:&error_response];
    if (SRFID_RESULT_SUCCESS == result)
    {
        power = [capabilities getMinPower];
    }

    /* prepare an object with desired antenna parameters */
    antenna_cfg = [[srfidAntennaConfiguration alloc] init];
    [antenna_cfg setLinkProfileIdx:link_profile_idx];
    [antenna_cfg setPower:power];
    [antenna_cfg setTari:tari];
    [antenna_cfg setDoSelect:NO];
    error_response = nil;
    /* set antenna configuration */
    result = [apiInstance srfidSetAntennaConfiguration:readerID aAntennaConfiguration:antenna_cfg aStatusMessage:&error_response];

    if (SRFID_RESULT_SUCCESS == result)
    {
      /* antenna configuration applied successfully */
      NSLog(@"Antenna configuration has been set\n");
    }
    else if (SRFID_RESULT_RESPONSE_ERROR == result)
    {
      NSLog(@"Error response from RFID reader: %@\n", error_response);
    }
    else if (SRFID_RESULT_RESPONSE_TIMEOUT == result)
    {
      NSLog(@"Timeout occurs during communication with RFID reader\n");
    }
    else if (SRFID_RESULT_READER_NOT_AVAILABLE == result)
    {
      NSLog(@"RFID reader with id = %d is not available\n", readerID);
    }
    else
    {
      NSLog(@"Request failed\n");
    }

}

Trigger Configuration

Overview

Gets and sets the start and stop trigger parameters of an active RFID reader, using srfidGetStartTriggerConfiguration and srfidSetStartTriggerConfiguration for the start trigger and srfidGetStopTriggerConfiguration and srfidSetStopTriggerConfiguration for the stop trigger.

Details

The SDK provides an ability to configure start and stop trigger parameters. Start trigger parameters include the following:

  • Start of an operation based on a physical trigger
  • Trigger type (press/release) of a physical trigger
  • Delay (in milliseconds) of start of operation
  • Repeat monitoring for start trigger after stop of operation

Start trigger configuration could be retrieved and set via srfidGetStartTriggerConfiguration and srfidSetStartTriggerConfiguration API functions accordingly.

Stop trigger parameters include the following:

  • Stop of an operation based on a physical trigger
  • Trigger type (press/release) of a physical trigger
  • Stop of an operation based on a specified number of tags inventoried
  • Stop of an operation based on a specified timeout (in milliseconds)
  • Stop of an operation based on a specified number of inventory rounds completed
  • Stop of an operation based on a specified number of access rounds completed

Stop trigger settings could be retrieved and set via srfidGetStopTriggerConfiguration and srfidSetStopTriggerConfiguration API functions accordingly.

The following examples demonstrate retrieval of current start and stop trigger parameters as well as configuring new start and stop triggers parameters.

Get Start Trigger Configuration

The getStartTrigger method retrieves the current start trigger parameters and prints them.


-(void)getStartTrigger{
    /* allocate object for storage of start trigger settings */

        NSLog(@"Start trigger: delay = %d ms\n", [start_trigger_cfg getStartDelay]);

Set Regulatory Configuration

The setRegulatoryConfig method selects the last supported region, enables hopping and channels where the region allows it, and applies the settings.


-(void)setRegulatoryConfig {
    /* an object for storage of error response received from RFID reader */
    NSString *error_response = nil;
    SRFID_RESULT result = SRFID_RESULT_FAILURE;

    /* code of region to be set as current one */
    NSString *region_code = @"USA";
    /* an array of enabled channels to be set */
    NSMutableArray *enabled_channels = [[NSMutableArray alloc] init];
    /* hopping to be set */
    SRFID_HOPPINGCONFIG hopping_on = SRFID_HOPPINGCONFIG_DISABLED;

    /* allocate object for storage of region information */
    NSMutableArray *regions = [[NSMutableArray alloc] init];

    /* retrieve supported regions */
    result = [apiInstance srfidGetSupportedRegions:readerID aSupportedRegions:&regions aStatusMessage:&error_response];

    if (SRFID_RESULT_SUCCESS == result)
    {

        /* supported regions information received */
        /* select the last supported region to be set as current one */
        region_code = [NSString stringWithFormat:@"%@", [(srfidRegionInfo*)[regions lastObject] getRegionCode]];

    }

    /* allocate object for storage of supported channels information */
    NSMutableArray *supported_channels = [[NSMutableArray alloc] init];
    BOOL hopping_configurable = NO;

    /* retrieve detailed information about region specified by region code */
    result = [apiInstance srfidGetRegionInfo:readerID aRegionCode:region_code aSupportedChannels:&supported_channels aHoppingConfigurable:&hopping_configurable aStatusMessage:&error_response];

    if (SRFID_RESULT_SUCCESS == result)
    {
        /* region information received */
        if (YES == hopping_configurable)
        {

            /* region supports hopping */
            /* enable first and last channels from the set of supported channels */
            [enabled_channels addObject:[supported_channels firstObject]];
            [enabled_channels addObject:[supported_channels lastObject]];
            /* enable hopping */
            hopping_on = SRFID_HOPPINGCONFIG_ENABLED;

        }
        else
        {
            /* region does not support hopping */
            /* request to not configure hopping */
            hopping_on = SRFID_HOPPINGCONFIG_DEFAULT;
        }
    }
    error_response = nil;
    /* configure regulatory parameters to be set */
    srfidRegulatoryConfig *regulatory_cfg = [[srfidRegulatoryConfig alloc] init];
    [regulatory_cfg setRegionCode:region_code];
    [regulatory_cfg setEnabledChannelsList:enabled_channels];
    [regulatory_cfg setHoppingConfig:hopping_on];

    /* set regulatory parameters */
    result = [apiInstance srfidSetRegulatoryConfig:readerID aRegulatoryConfig:regulatory_cfg aStatusMessage:&error_response];
    if (SRFID_RESULT_SUCCESS == result)
    {
        /* regulatory configuration applied */
        NSLog(@"Regulatory configuration has been set\n");
    }
    else if (SRFID_RESULT_RESPONSE_ERROR == result)
    {
        NSLog(@"Error response from RFID reader: %@\n", error_response);
    }
    else
    {
        NSLog(@"Failed to set regulatory parameters\n");
    }
}

Performing Operations

Rapid Read

Overview

Performs a rapid read, a simple inventory without reading from a particular memory bank, using srfidStartRapidRead and srfidStopRapidRead.

Details

Rapid read operation is a simple inventory operation without performing a read from a particular memory bank.

The srfidStartRapidRead API function is used to request performing of rapid read operation. Aborting of rapid read operation is requested via srfidStopRapidRead API function. When performing of rapid read operation is requested the actual operation will be started once conditions specified by start trigger parameters are met. The on-going operation will be stopped in accordance with configured stop trigger parameters. If repeat monitoring option is enabled in start trigger configuration the actual operation will be started again after it has stopped once conditions of start trigger configuration are met. On starting and stopping of the actual operation the SDK will deliver asynchronous notifications to the application if the application has subscribed for events of this type.

The SDK will deliver asynchronous notifications to inform the application about tag data received from the RFID reader during the on-going operation if the application has subscribed for events of this type. Fields to be reported during asynchronous tag data related notification are configured via reportConfig parameter of srfidStartRapidRead API function.

The following examples demonstrate performing of rapid read operation that starts and stops immediately after requested operation performing and aborting.

Start and Stop Rapid Read

    srfidReportConfig *report_cfg = [[srfidReportConfig alloc] init];

            }

                NSLog(@"Failed to set stop trigger parameters\n");
                break;
            }

            }

Inventory

Overview

Performs an inventory, an advanced inventory that reads from a particular memory bank at the same time, using srfidStartInventory and srfidStopInventory.

Details

Inventory is an advanced inventory operation being performed simultaneously with reading from a particular memory bank.

Inventory operation is performed similarly to the rapid read operation described above. Thus performing and aborting of the inventory operation is requested through srfidStartInventory and srfidStopInventory API functions accordingly. After request of operation performing the actual operation will be started in accordance with the configured start trigger parameters and will be stopped once conditions specified by stop trigger parameters are met. Multi Tag Locationing

Overview

Locates several tags at once, using srfidStartMultiTagsLocationing and srfidStopMultiTagsLocationing.

Details

Multi tag locationing looks for several tags at the same time. Give the SDK a list of tag IDs, each with an RSSI limit in dBm, and the reader reports a tag only when its signal is stronger than its limit. For example, with a limit of -40 dBm a tag at -45 dBm is not reported.

Access Operations

Overview

The SDK supports performing of read, write, lock and kill access operations on a specific tag. Access operations are performed via srfidReadTag, srfidWriteTag, srfidLockTag and srfidKillTag API functions accordingly. The mentioned API functions are performed synchronously; the corresponding operation is started immediately and is stopped once tag data is reported by RFID reader or after a 5 seconds timeout.

Access operations use two types that the SDK defines. SRFID_MEMORYBANK selects the memory bank of the tag:

  • SRFID_MEMORYBANK_EPC (0x01)
  • SRFID_MEMORYBANK_TID (0x02)
  • SRFID_MEMORYBANK_USER (0x04)
  • SRFID_MEMORYBANK_RESV (0x08)
  • SRFID_MEMORYBANK_NONE (0x10)
  • SRFID_MEMORYBANK_ACCESS (0x20)
  • SRFID_MEMORYBANK_KILL (0x40)
  • SRFID_MEMORYBANK_ALL (0x67)

SRFID_ACCESSPERMISSION sets the access permission when a memory bank is locked:

  • SRFID_ACCESSPERMISSION_ACCESSIBLE (0x00)
  • SRFID_ACCESSPERMISSION_ACCESSIBLE_PERM (0x01)
  • SRFID_ACCESSPERMISSION_ACCESSIBLE_SECURED (0x02)
  • SRFID_ACCESSPERMISSION_ALWAYS_NOT_ACCESSIBLE (0x03)

Read and write are described on the Read and Write page, kill on the Kill page and lock on the Lock page.

Read and Write

Overview

Reads data from, and writes data to, a memory bank of a specific tag, using srfidReadTag and srfidWriteTag.

Details

The tag ID is the tag's EPC as a hexadecimal string, for example one read by an inventory. Data to write is also a hexadecimal string, with four characters per 16-bit word.

In the EPC memory bank, word 0 is the CRC and word 1 is the PC. The EPC itself starts at word 2. The read below starts at word 0, so it returns the CRC, the PC and the first six words of the EPC. The write starts at word 2, so it replaces the 96-bit EPC (six words, 24 hexadecimal characters). Do not write the EPC at word 0, because that overwrites the CRC and PC words.

The write changes the tag. Use a tag you can afford to change, and note its original EPC so you can write it back. After the write, the tag answers to its new EPC, so use the new EPC as the tag ID to address it again.


-(void)accessOperationTagReadAndWrite {

    /* allocate object for storing results of access operation */
    srfidTagData *access_result = [[srfidTagData alloc] init];
    /* id of tag to be read (the EPC, as a hexadecimal string) */
    NSString *tag_id = @"E28011B0A506007D3DD17A34";
    /* an object for storage of error response received from RFID reader */
    NSString *error_response = nil;

    /* request to read 8 words from EPC memory bank of tag specified by tag _id */
    SRFID_RESULT result = [apiInstance srfidReadTag:readerID aTagID:tag_id aAccessTagData:&access_result aMemoryBank:SRFID_MEMORYBANK_EPC aOffset:0 aLength:8 aPassword:0x00 aStatusMessage:&error_response];

    if (SRFID_RESULT_SUCCESS == result) {
        NSLog(@"Request succeed\n");

        /* check result code of access operation */
        if (NO == [access_result getOperationSucceed]) {
            NSLog(@"Read operation has failed with error: %@\n", [access_result getOperationStatus]);
        }
        else {
            NSLog(@"Memory bank data: %@", [access_result getMemoryBankData]);
        }
    }
    else if (SRFID_RESULT_RESPONSE_ERROR == result) {
        NSLog(@"Error response from RFID reader: %@\n", error_response);
    }
    else if (SRFID_RESULT_RESPONSE_TIMEOUT == result) {
        NSLog(@"Timeout occurred\n");
    }
    else {
        NSLog(@"Request failed\n");
    }

    access_result = [[srfidTagData alloc] init];
    error_response = nil;

    /* data to be written: a new 96-bit EPC, as 24 hexadecimal characters */
    NSString *data = @"ABCDEF0123456789ABCDEF01";

    /* request to write a data to a EPC memory bank of tag specified by tag_id, starting at word 2 (the EPC) */
    result = [apiInstance srfidWriteTag:readerID aTagID:tag_id aAccessTagData:&access_result aMemoryBank:SRFID_MEMORYBANK_EPC aOffset:2 aData:data aPassword:0x00 aDoBlockWrite:NO aStatusMessage:&error_response];

    if (SRFID_RESULT_SUCCESS == result) {
        NSLog(@"Request succeed\n");

        /* check result code of access operation */
        if (NO == [access_result getOperationSucceed]) {
            NSLog(@"Write operation has failed with error: %@\n", [access_result getOperationStatus]);
        }
    }
    else if (SRFID_RESULT_RESPONSE_ERROR == result) {
        NSLog(@"Error response from RFID reader: %@\n", error_response);
    }
    else if (SRFID_RESULT_RESPONSE_TIMEOUT == result) {
        NSLog(@"Timeout occurred\n");
    }
    else {
        NSLog(@"Request failed\n");
    }

}

Overview

This API is used to execute multiple access operations (Read, Write, etc) at the same time.


- (SRFID_RESULT) srfidPerformAccessInSequence:(int)readerID aAccessCriteria:(srfidAccessCriteria*)accessCriteria aAccessParameters: (NSArray *)accessParameters aStatusMessage:(NSString**)statusMessage;

Parameters


(int)readerID
   [in] Unique identifier of a particular RFID reader assigned by SDK.

   [in] Access criteria to identify the tag on which the access operations are performed. Using the access criteria, a tag can be chosen with the data of one of its memory banks.

SRFID_RESULT_FAILURE

   An error has been reported by the RFID reader via ASCII interface.

Perform Access in Sequence

The accessSequence method sets up the access criteria and parameters and starts the sequence with srfidPerformAccessInSequence.

The call only arms the reader. The sequence runs while the start trigger is active, for example the hand-held trigger, and keeps running until it is stopped with srfidAccessSequenceStop or by the stop trigger. Starting a sequence while another is armed fails with the message "Operation In Progress-Command Not Allowed". The result of each operation is delivered in srfidEventReadNotify:, not returned by the call.

The write operation changes the tag. The example writes the tag's own EPC at word 2, so the EPC stays the same. Use a tag you can afford to change if you write any other data. Put an operation that can fail, such as reading the USER memory bank of a tag without user memory, last: the operations after a failed operation do not report a result.


-(void)accessSequence{

    // initialize access criteria
    srfidAccessCriteria *accessCriteria = [[srfidAccessCriteria alloc] init];
    // setup tag filter 1
    srfidTagFilter *tagFilter1 = [[srfidTagFilter alloc] init];
    [tagFilter1 setFilterMaskBank:SRFID_MEMORYBANK_EPC];
    [tagFilter1 setFilterData:@"E2806894000040065071E164"];
    [tagFilter1 setFilterDoMatch:YES];
    [tagFilter1 setFilterMask:@"FFFFFFFF"];
    [tagFilter1 setFilterMaskStartPos:2];
    [tagFilter1 setFilterMatchLength:2];
    [accessCriteria setTagFilter1:tagFilter1];

    NSMutableArray *accessParamsArray = [[NSMutableArray alloc]init];
    [accessParamsArray addObject:[self setAccessParamsForRead:SRFID_ACCESSOPERATIONCODE_READ memoryBank:SRFID_MEMORYBANK_EPC offset:0 length:8 password:0]];
    [accessParamsArray addObject:[self setAccessParamsForRead:SRFID_ACCESSOPERATIONCODE_READ memoryBank:SRFID_MEMORYBANK_TID offset:0 length:2 password:0]];
    [accessParamsArray addObject:[self setAccessParamsForRead:SRFID_ACCESSOPERATIONCODE_READ memoryBank:SRFID_MEMORYBANK_RESV offset:0 length:4 password:0]];
    /* write the tag's own EPC back at word 2 (the EPC starts at word 2), so the tag keeps its EPC */
    [accessParamsArray addObject:[self setAccessParamsForWrite:SRFID_ACCESSOPERATIONCODE_WRITE memoryBank:SRFID_MEMORYBANK_EPC offset:2 password:0 doBlockWrite:NO dataToWrite:@"E2806894000040065071E164"]];
    /* read the USER memory bank last: on a tag without user memory this read fails */
    [accessParamsArray addObject:[self setAccessParamsForRead:SRFID_ACCESSOPERATIONCODE_READ memoryBank:SRFID_MEMORYBANK_USER offset:0 length:0 password:0]];

    SRFID_RESULT result;
    result = [apiInstance srfidPerformAccessInSequence:self->readerID aAccessCriteria:accessCriteria aAccessParameters:accessParamsArray aStatusMessage:nil];
    NSLog(@"Result Perform Access In Sequence %u",result);

}

Access Sequence APIs

Overview

An access sequence lets you queue several tag operations (read, write, and so on) and run them together. The workflow has three steps:

  1. Buffer Management: build the list of operations to run.
  2. Execution and Control: start and stop the sequence.
  3. Monitoring and Tag Retrieval: get the results and the tag data.

In the samples, apiInstance is your SDK instance and readerID is the ID of the connected reader.

Buffer Management

Build the list of operations to run.

Creating operations

readOp.password   = 0;      // access password (0 if none)

Complete Example


NSString *statusMessage = nil;

Reader Logging

Get Reader Log

Overview

Helps support and engineering diagnose RFID reader behaviour in the field: stream live diagnostics while work is happening, and pull stored log files from the reader for deeper analysis.

Retrieves the log data stored on the RFID reader, from its RAM and FLASH log files, using srfidGetReaderLog.

Details

Start retrieval of the log data stored in the reader RAM and FLASH log files in one operation. The call needs an administrator login first (see Login Support for E8 Devices). Without it the call fails with the message "User has not logged as an admin".

The log text is not returned by the call. The reader sends it as debug events, first the RAM log and then the FLASH log. To receive them, subscribe to SRFID_EVENT_MASK_DEBUG_INFO and handle SRFID_EVENT_STATUS_DEBUG_INFO in srfidEventStatusNotify:aEvent:aNotification:. The event data is an srfidNotificationDebugEvent: read the text with getMessage and the level with getLevel.


- (SRFID_RESULT)getReaderLog:(NSString**)statusMessage
{
    // Subscribe to the reader's log lines
    [apiInstance srfidSubsribeForEvents:SRFID_EVENT_MASK_DEBUG_INFO];

    SRFID_RESULT srfid_result = [apiInstance srfidGetReaderLog:readerID
                                                      logState:SRFID_LOGSTATE_INTERNALRAMANDFLASHLOGSTATE
                                                aStatusMessage:statusMessage];

    if (srfid_result == SRFID_RESULT_FAILURE || srfid_result == SRFID_RESULT_RESPONSE_TIMEOUT)
    {
        NSLog(@"Failure");
    }
    return srfid_result;
}

Add this to your srfidEventStatusNotify:aEvent:aNotification: to receive the log lines:


- (void)srfidEventStatusNotify:(int)readerID aEvent:(SRFID_EVENT_STATUS)event aNotification:(id)notificationData {

        NSLog(@"Reader log [level %d]: %@", [logEvent getLevel], [logEvent getMessage]);
    }
}

/// This method will initiate the connection with particular scanner
/// @param scanner_id Scanner id of the connecting scanner
-(void)connectScanner:(int)scanner_id{
    if (sdkApi != nil)
    {
      if(scanner_id != -1 )
      {
        SBT_RESULT conn_result = [sdkApi sbtEstablishCommunicationSession:scanner_id];

        if (SBT_RESULT_SUCCESS != conn_result)
        {
            NSLog(@"Scanner connection failed");
        }
      }
    }
}

Disconnect Scanner

Overview

Terminates the communication session with an active scanner, using sbtTerminateCommunicationSession.

Details

Requests to terminate communication session with a particular active scanner


/// This method will initiate the disconnection with particular scanner
/// @param scannerId Scanner id of the disconnecting the scanner
- (void)disconnect:(int)scannerId
{

    if (sdkApi != nil)
    {
        SBT_RESULT res = [sdkApi sbtTerminateCommunicationSession:scannerId];
        if (res == SBT_RESULT_FAILURE) {
            NSLog(@"Scanner disconnect failed");
        }
    }
}
