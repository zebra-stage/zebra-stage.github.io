Enumerations

Reference·Audience: API consumer·Use: look up the exact values an enumerated field accepts or reports

Values are case-sensitive and must be sent exactly as shown. Enumerations are closed: a schema validator rejects any other value. Where a note describes firmware support, the value is valid on the wire but current firmware reports it only in the places named.

connectionState​

Connection state. JSON type string. The contract uses two enumerations with different casing.

ValueNote
CONNECTEDalerts network items, get_status (radioConnection, terminalConnection.status), get_wifi (accessPoint.status), and mqttConnEVT
DISCONNECTEDThe same members
Connectedget_eth only, in linkStatus.status
DisconnectedThe same member

Compare case-insensitively if one code path handles both.

mqttQoS​

MQTT Quality of Service level. JSON type integer. Used by config_endpoint, get_endpoint_config.

The contract declares qos and qosCommon as integers without an enumeration or a default. MQTT 3.1.1 defines the levels 0, 1 and 2; which levels the reader honors is not specified in the available sources. The contract's examples use 0 and 1.

IoTC status code: response.code. JSON type integer, from 0 to 101. Used by 20 pages.

verificationType​

TLS verification mode. JSON type string. Used by config_endpoint, get_endpoint_config, install_certificate, set_os.

This documentation describes two values:

ValueNote
VERIFY_HOST_AND_PEERVerify the broker's certificate chain and that the certificate matches the host. Use it in production.
VERIFY_NONENo verification. Must not be used in production. An MQTT_TLS endpoint rejects it with code 37.
