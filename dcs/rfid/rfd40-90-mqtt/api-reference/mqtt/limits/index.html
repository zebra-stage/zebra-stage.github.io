Limits

Reference·Audience: All personas·Use: capacity planning and pre-flight checks

Every limit the MQTT API contract declares, in one place. Where the Enforced by column names a response code, the reader rejects a value past the limit with that code; every code is listed in Response Codes. The field-level definitions are in the MQTT API reference.

Events​

LimitValueEnforced by
Heartbeat intervalAt most 65,535 seconds. No minimum and no default are declaredNot specified in the available sources

The MQTT keep-alive in the contract's server binding is 300 seconds. It is the binding's value, not a declared limit.

Where a row cites Zebra's release notes, the figure is from the RFD40/RFD90 release notes for SAAFKS00-013-R05 rather than from the contract, and it is the firmware's behavior rather than a schema constraint. Two of them disagree with the contract or are scoped more narrowly than they first read: the contract sets no bound on endpointName while the release notes say 15, so keep endpoint names to 15; and the endpoint and Wi-Fi counts are stated for configurations loaded by 123RFID offline configuration, not for what config_endpoint and set_wifi accept over MQTT.

A Wi-Fi or endpoint change needs a reboot to take effect, per the same release notes. See What a Reboot Changes.
